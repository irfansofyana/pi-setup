# First-party subagents — inactive M0/M1 with partial M2 lifecycle core

Package glob auto-loads `index.ts`, but this entrypoint is intentionally inert. It never registers a tool, command, event listener, provider, timer, worker or storage. `PI_SETUP_SUBAGENTS_ENABLED` does **not** activate it. Tintinweb remains the companion in `package.json`; do not remove, disable or duplicate it. `/reload` is unnecessary until an approved activation change exists.

## Frozen draft contract

- `contracts.ts` defines version 1 IDs, control vocabulary, run states, typed outcomes/receipts and capacity ceilings. `supervisor.ts` implements an **in-memory lifecycle core**, not full M2. Message is context-only; steer and interrupt require the current run ID. Follow-up is a distinct queued/admitted run on the same thread, reusing a live backend session (never native `followUp()`). Resume with a new message admits a new run only when a completed live thread's backend attests authoritative retained context; stopped, disposed, metadata-only and restarted threads reject it. Waiter timeout/cancellation does not abort the worker. No operation is reachable through the inert entrypoint.
- A receipt of `queued` or `handled` is not proof of model delivery. Only an actually verified injection can be labelled `applied`; unknown delivery stays explicit. Incomplete/partial output is never accepted work. `completed` denotes technical settlement, not verified task quality.
- IDs are separate agent/thread/run/control namespaces; the caller supplies a collision-resistant generator, validated and collision-checked at admission. UTF-8 ceilings are in `limits`. Runs reserve result slots before admission; consumption releases reservations but retains history until bounded consumed-detail pruning. Closed threads release thread capacity, including when they contain unconsumed results: those results remain retrievable and keep their result reservation. Fully consumed closed threads are pruned; consumed older runs in open threads are pruned at the result-slot detail cap. Unconsumed results are never evicted to admit work. There is no disk spill.
- Legacy tool evidence is sanitized in `legacy-fixture.json`, sourced from the *currently installed* Tintinweb 0.19.0. Earlier due diligence recorded 0.14.3. The installed copy has since changed: **do not claim 0.14.3 field-for-field parity** without obtaining that version's source. M0 validation intentionally rejects unsupported scheduling, inheritance, isolated execution and fuzzy model names even when upstream accepts them. Protocol v2 replies and event keys are evidence fixtures, not an operational adapter. No ambiguous legacy field is silently ignored.
- Trusted user-owned global role definitions must be supplied by an approved resolver. `roles.ts` does not discover or load roles, extension factories, tools, skills or models. It requires exact canonical resource sets, disabled session/transcript/context inheritance and a worktree for builder. Missing resources/models or untrusted/project roles fail closed. Headroom is routing-only and **optional**: explicit `routing: "native"` removes it from the effective extension requirement without broadening tools/skills; explicit `routing: "headroom"` requires it. Unconfigured callers remain fail-closed on the old Headroom requirement until a reviewed configuration-to-mode resolver exists. Invocation turn caps may **lower** a role ceiling; soft limit requests wrap-up and hard stop is soft + five grace turns. This changes older frontmatter-overrides-caller semantics. The Goal evaluator's `Explore` hard-two-turn, zero-grace alias is **not enabled**: a dedicated reviewed read-only loadout is required. `scopeModels` remains a guardrail, not an authorization boundary; exact explicit models must exist.
- Configuration ownership: this package owns only code and proposed defaults. Global role files and `~/.pi/agent/subagents.json` remain user-owned. No env flag, project file or ambient package setting can activate M0. `isolatedProfile()` is a declarative temporary-home rehearsal inventory, not an actual Pi loader configuration or active test. M1 must demonstrate a companion-exclusive isolated loader and provider/runtime feasibility before introducing a deliberate pre-registration activation gate. No live `~/.pi` mutation or provider-backed test is part of M0.

No provider secret, HTTP transport or persistent child/settings store is used. `backend.ts` remains unreachable from the inert `index.ts`; no visible Pi command/tool or full MVP exists yet.

Evidence is against the **installed `@earendil-works/pi-coding-agent` 1.1.0**, verified after local dependency repair; it is not evidence for the root manifest's Pi `>=1.0.0` floor. RPC was not investigated because this public path works for the constrained fake. The backend rejects non-fixture providers, non-read tools and extension requests with typed failures; its generic `control` rejects unimplemented operations. This is an explicit fake-provider seam, **not** production model/auth discovery or a generic provider adapter.

Control findings: context-only `sendCustomMessage({triggerTurn:false,deliverAs:'nextTurn'})` leaves an idle session idle; its receipt is `unknown_delivery`, not proof of later model consumption. Active `steer` returns Pi's `queued`/`handled` disposition, not a proven injection receipt. `abort` clears the native queue, requests cooperative cancellation, and labels resulting work incomplete/interrupted; it cannot undo tool side effects. Unsupported follow-up/admission, resource discovery, retries/compaction/handled prompt accounting, initialization cancellation and shutdown lease handling are still gates. In particular **canonical child Headroom/approved-factory/skill integration, real custom-provider inheritance, exact real model/auth resolution and Pi 1.0.x route compatibility remain untested**. Do not activate or cut over from Tintinweb based on this spike.

The source version drift and companion-exclusive active loader rehearsal remain open review gates. Passing tests do not establish real-provider compatibility or a full MVP.

**Narrow Headroom child routing bridge (`@earendil-works/pi-coding-agent` 1.1.0 only):** `pi/extensions/headroom/index.ts` exports `acquireHeadroomChildRoute`, a deliberately non-default, non-activating lease for a *preexisting* parent-owned route on the **same** `ModelRuntime`. ## M2 bounded supervisor slice (not activated)

`createSupervisor({createBackend,nextId,concurrency?,pending?,slots?,bytes?,threads?})` owns one FIFO queue (default concurrency 3), per-run state, open→closing→closed threads and correlated raw SDK events. A live backend is retained by its open thread across follow-ups and disposed on close/shutdown; interrupted runs discard their backend and cancel pending follow-ups rather than continue without context. Each run has its own result/promise/stop state. Queued interrupt resolves `cancelled`; active interrupt requests cooperative abort and labels eventual result incomplete even if the backend reports success. Active and initializing workers hold slots until settlement/cleanup; failed disposal quarantines ownership and makes `dispose()` reject. `wait([runId],signal,timeoutMs)` rejects on waiter abort/timeout without stopping work. `result` and `consume` may target an old run with `expectedRunId`; default is the current run. Immutable terminal results remain inspectable after consumption until the documented consumed-detail pruning policy applies. Per-run text preview is capped at 256 KiB. A terminal `completed` result is SDK settlement, not task verification. Raw subscriber events are live-only; consumers must handle sensitive tool output and their own buffering. Message/steer receipts identify the current run; native `queued`/`handled` and context-message `unknown_delivery` do not prove application. A bounded mailbox queues context during initialization/idle time, and missing backend delivery fails the run before prompting rather than silently dropping context.

`native-supervisor.test.ts` exercises **two** real in-process Pi SDK sessions with separate fake provider instances, read-only `read` calls, streamed text/tool events, terminal results and temporary directories. Run `node --test pi/extensions/subagents/*.test.ts`; there is deliberately **no CLI/TUI preview** and no import from `index.ts`. The fake provider cannot reach a real model or network, and the test checks the temporary agent directory and fixture cwd for unexpected writes.

This is not full M2: no real-provider/role loadout integration, true forks or persisted restoration, owner-generation notifications, durable storage or reattachment. The mailbox only bounds supervisor-owned input; once a message crosses the native SDK boundary, injection remains unproven. Resume cannot reconstruct a closed or restarted thread; no fallback to fresh or broader context. A hung backend can keep its slot and delay `dispose()` indefinitely; this is intentional rather than falsely releasing a live worker. M3 fleet UI, legacy tools/protocol and Pi activation are untouched. Do not cut over from Tintinweb based on this core.

## M2 observed-budget slice (still inactive)

A trusted caller may supply `createSupervisor({ budget: { softTurns, hardTurns, elapsedMs?, maxTokens?, maxCost? }, evaluatorSupported? })`. The optional invocation `maxTurns` can lower, never enlarge, the supplied canonical role ceiling; hard is bounded by the canonical hard ceiling and retains its original grace span. The optional evaluator request is rejected unless explicitly supported and the canonical ceiling allows two turns; it then uses hard two with zero grace. This is a supervisor seam, **not** integration with installed role definitions or authorization of the Goal evaluator loadout. Without a supplied budget, existing in-memory callers remain unbudgeted; do not expose this path as an active role runner.

Finalized assistant `message_end` events are counted once per run/message ID (or native object identity where Pi supplies no ID); thread totals survive follow-ups and admitted live resumes without resetting budgets. Soft turns request wrap-up through native steer when available; hard turns request cooperative abort and keep their slot until settlement. Elapsed deadlines use a monotonic clock shared across a thread's follow-ups, starting with its first run; the clock may be injected for deterministic tests. Usage reports disjoint input, output, cache-read, cache-write, summed tokens and observed total cost. Under a token/cost threshold, absent/malformed finalized usage or a completed run with no finalized assistant usage fails closed. Threshold crossings mark `budget_exhausted` and incomplete, but **in-flight requests and asynchronous abort can overshoot**; these are observed thresholds, **not hard token or billing caps**. Parent/descendant aggregate usage is not accepted as a native message event: explicitly run-tagged foreign events are ignored, while each native Pi session belongs to one thread. M7 ancestry accounting/ownership remains a gate. The native offline Pi test verifies two finalized assistant messages and four observed tokens from its fake provider, with no network or added files.

Lifecycle regression: closing during an asynchronous mailbox delivery no longer sends later queued context messages after cancellation. A delivery already in flight cannot be retracted.

## M2 explicit context snapshot (offline, inactive)

Fresh remains the default. A trusted caller opts in with `{role, context:{mode:"snapshot",sourceSessionId,branchLeafId,entryAnchorId}}` and a trusted `resolveSource(sessionId)` returning the exact Pi `SessionManager`; no ambient parent selection or path lookup occurs. The source leaf must match the requested active branch, and the anchor must be on that branch. `buildSessionProjection(source.getEntries(), anchor)` resolves the selected path using Pi's compaction/context-edit machinery; the transfer copies only plain user/assistant/tool-result context with complete tool-call/result pairs. Missing, abandoned, partial-tool and empty anchors reject. Custom messages, branch summaries, compactions, context edits, images and non-text tool results reject rather than risking an ambiguous/private summary or invisible payload. State-only model, thinking, usage, labels and custom metadata do not cross. The whole serialized payload (messages, entry IDs, lineage and policy) is capped at 128 KiB; it is not truncated. The resolved snapshot records source session, active leaf, entry anchor, entry IDs, excluded categories, cap and measured bytes. The supervisor resolves this *before* queue admission; the offline native backend seeds a new `SessionManager.inMemory()` via public `appendMessage` and still constructs its own explicitly scoped model, tools, loader and settings. Ciung/researcher rejects automatic local parent-context transfer even if an explicit request is supplied. Filtering cannot certify that ordinary text or tool output contains no secrets; only reviewed/trusted sources should be selected.

True fork is **typed `unsupported_fork` before source access or backend creation**. Installed Pi 1.1.0 exposes `SessionManager.createBranchedSession(leafId)` (persisted unfiltered path) and `SessionManager.forkFrom(sourcePath,targetCwd)` (full persisted source history), not a public bounded/filterable fork operation. Calling either would copy source state and/or require persistence outside this no-write child contract. An in-memory snapshot is not mislabelled a true fork. `context.test.ts`, `context-supervisor.test.ts`, and the native fake-provider test in `backend.test.ts` exercise anchor selection, disallowed categories, paired tools, byte cap, pre-admission failures, new-run live resume and selected-context delivery without provider network or child files. Pi >=1.0.0 compatibility and provider-backed behavior remain unproven.
